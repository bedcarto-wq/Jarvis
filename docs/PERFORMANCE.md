# Производительность JARVIS

JARVIS рассчитан на обычные домашние и офисные ПК без видеокарты и без нейросетей. Все «тяжёлые» места
(распознавание речи, OCR, обход интерфейса UI Automation, ожидания в шаблонах, фоновые задачи) управляются
**одним набором параметров** — каталогом `PerformanceCatalog` (`src/JARVIS.Core/Performance/PerformanceParameters.cs`).
Профиль — это просто набор значений этих параметров. Разбросанных по коду «если слабый ПК, то…» нет.

## Где применяются параметры

| Ключ | Параметр | Где используется в коде |
|---|---|---|
| `hud.animations` | Анимации HUD | `HudWindow` (пульсация и переходы) |
| `hud.refreshMs` | Частота обновления HUD (индикатор микрофона) | таймер в `App.xaml.cs`, меняется на лету |
| `exec.stepDelayMs` | Пауза между шагами шаблона | `TemplateExecutor` |
| `exec.typingDelayMs` | Задержка между символами при вводе | `InputService` через `ActionRunner` |
| `exec.launchTimeoutMs` | Ожидание окна после запуска | `AppLaunchCoordinator` (при медленном запуске ждёт ещё раз, если процесс жив) |
| `exec.windowPollMs` | Интервал проверки появления окна | `ActionRunner.WaitForWindowAsync` |
| `exec.elementPollMs` | Интервал проверки элемента | блок «Ожидать элемент» |
| `exec.elementWaitTimeoutMs` | Тайм-аут ожидания элемента по умолчанию | блок «Ожидать элемент» |
| `ui.windowCacheMs` | Кэш списка окон | `WindowService` (сбрасывается после любого действия с окном) |
| `ui.uiaMaxElements` | Максимум элементов при обходе UI Automation | `VisionService` |
| `ui.uiaWalkTimeMs` | Лимит времени обхода UI Automation | `VisionService` |
| `ocr.scale` | Увеличение снимка для OCR | `TesseractOcr` |
| `ocr.maxWindows` | Сколько окон просматривает OCR за один поиск | `VisionService` |
| `voice.maxHmmPf` | `maxhmmpf` PocketSphinx | `PocketSphinxEngine` (перезапуск распознавателя) |
| `voice.beamExp` | `beam = 1e-N`, `wbeam = 1e-(N-10)` | `PocketSphinxEngine` (перезапуск распознавателя) |
| `bg.maxTasks` | Параллельных фоновых задач | `BackgroundGate` (поиск программ), `AppDiscovery` |
| `mon.intervalMs` | Интервал лёгкого мониторинга | `MonitoringService` |

## Базовые профили

| Параметр | «Средний ПК» | «Слабый ПК» | Почему так на слабом ПК |
|---|---|---|---|
| Анимации HUD | вкл. | выкл. | анимации WPF постоянно перерисовывают окно |
| Обновление HUD | 150 мс | 400 мс | меньше пробуждений UI-потока |
| Пауза между шагами | 150 мс | 250 мс | медленные программы успевают отреагировать |
| Ввод текста | 5 мс/символ | 10 мс/символ | меньше пропусков символов в «тяжёлых» окнах |
| Ожидание окна после запуска | 5 с | 12 с | на HDD программы стартуют дольше |
| Проверка окна / элемента | 250 / 500 мс | 500 / 1000 мс | вдвое меньше опросов |
| Ожидание элемента | 10 с | 20 с | медленная отрисовка интерфейса |
| Кэш списка окон | 300 мс | 1000 мс | перечисление окон не повторяется на каждом шаге |
| Элементов UIA / лимит обхода | 4000 / 2,5 с | 1500 / 4 с | меньше элементов, но больше времени на медленном CPU |
| OCR: масштаб / окон | 2× / 3 | 1,5× / 1 | в 1,8 раза меньше пикселей, один снимок |
| `maxhmmpf` / beam | 3000 / 1e-30 | 1500 / 1e-25 | меньше гипотез на кадр, ниже нагрузка CPU при распознавании |
| Фоновых задач | 2 | 1 | фоновая работа не конкурирует с командами |
| Мониторинг | 2 с | 5 с | |

Все основные функции остаются доступными в обоих профилях: меняется только расход ресурсов и тайм-ауты.
Параметры безопасности (подтверждения, опасные действия, слово-стоп) **не входят** в профили и не могут быть изменены
профилем или импортом — такие ключи отбрасываются с предупреждением (`PerformanceCatalog.ForbiddenKeys`).

## Пресеты

«Максимальная экономия», «Сбалансированный», «Быстрый отклик», «Работа с несколькими приложениями» — готовые наборы,
которые можно применить или скопировать в свой профиль. Значения — в `BuiltInProfiles.Presets`.

## Мониторинг

Отдельная функция, не связанная с бенчмарком. Включается/выключается флажком на странице «Производительность».
Показывает активный профиль, текущую задачу, CPU и память процесса JARVIS (через `Process`), число потоков.
Если значение получить нельзя — «Недоступно», а не ноль. Дорогих измерений мониторинг не делает и полный
бенчмарк не запускает.

## Что проверено

* Применение профиля, сохранение после перезапуска, сравнение, отсутствие параметров безопасности — автотесты (Linux, .NET).
* Реальное влияние `maxhmmpf`/`beam` на скорость декодера — замер RTF на Linux с настоящим PocketSphinx.
* Влияние на HUD, UI Automation и OCR в Windows — **требует ручной проверки на Windows** (собирается и запускается в CI).
